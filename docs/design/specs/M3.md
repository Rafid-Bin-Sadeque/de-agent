# M3 spec: Redshift collector, AWS collectors, Redshift audit pack, AWS lineage edges

Depends on M1a–M2. Zero company data: every identifier, number and example is fictional (Acme). Neither Redshift nor AWS can run
in the local demo, so correctness comes from moto, botocore Stubber fixtures and an optional live read-only check by the maintainer (§7).

Approved for the executor: repo edits, cli/.venv pip (incl. `boto3`, `moto[all]` as dev/optional deps), local docker, local commits,
scratch dir. Not approved: push, publish, global installs, non-local hosts. §7 runs only if the maintainer approves it separately.

## 0. M2 carry-overs (first, separate commit `M2.1: recovered signals, demo long-query root cause`)

1. **Recovered signals.** If a DAG's latest run succeeded after its last failure in the 24 h window, the failure signal still appears but
   is labelled `(recovered: last run <state> at <time>)` and ranked below active signals. `dea diff` reports `RECOVERED signal: …`.
   Apply the same rule to dbt (a later successful run clears failing nodes). Tests with fixtures.
2. **Demo "query running > 5 min".** Find the root cause of the signal that appeared after the walkthrough, with evidence from
   pg_stat_activity. If it's noise (the collector's own backend, an idle Airflow metastore connection, a `walsender`, `autovacuum`),
   fix the filter and add a test. If it's real (a leftover session from a fault), fix the fault's revert. Report which it was.
3. Add `.DS_Store` to `.gitignore`.

## 1. Redshift collector: `collectors/redshift.py`

**Config**
```yaml
- {name: dwh, type: redshift, conn: {host: …, port: 5439, dbname: dev, user: readonly_agent, password: pgpass}, exec: local|ssh:<host>}
- {name: dwh, type: redshift, data_api: {cluster_id: acme-dwh | workgroup: acme-wg, database: dev, db_user: readonly_agent | secret_arn: "env:…"},
   aws: {profile: readonly, region: …}}
```
Two transports: the PG wire protocol (psycopg / psql, the same secret rules as postgres) or the Redshift Data API (boto3, IAM, no password).

**Execution**
- Redshift has no `json_agg` and no `lock_timeout`. Add a Redshift wrapper in `sqlexec`:
  - `BEGIN READ ONLY` → `SET statement_timeout` → query → `ROLLBACK`.
  - Rows come back through the cursor (psycopg), or via `psql --csv` (ssh) parsed with column types, or Data API records.
- All three paths must return the same JSON shape. A golden test feeds one result set through each.
- Section timeouts default to 60 s. On timeout or permission error the section records the error and the rest continue. Report timings per section.

**Versions:** prefer `SYS_*` views (provisioned + serverless). If a `SYS_` view is missing, fall back to `STL/STV/SVL`, and record which
source was used per section.

**Sections**
| section | content |
|---|---|
| `cluster` | version, node count/slices (stv_slices), serverless vs provisioned, plus describe_clusters/get_workgroup when `aws:` is set |
| `workload_24h` | exec-time share by user and by query_type; top 15 queries by total exec time (normalized text ≤ 200 chars, count, avg/max s); queue wait p50/p95 |
| `pressure_24h` | queries that spilled to disk (count, total MB), commit queue wait p95, peak concurrency per hour, top alert events (stl_alert_event_log) |
| `tables` | top 50 by size from svv_table_info: size MB, rows, unsorted %, stats_off, skew_rows, diststyle, sortkey1 |
| `locks` | blocked/blocking sessions and long open transactions (svv_transactions, stv_locks) |
| `load_errors_24h` | recent COPY/load errors (table, column, error, count) |
| `maintenance` | auto-vacuum/auto-analyze recent activity when visible |

**Signals**
- one user > 70% of exec time over 24 h ("workload is dominated by X; check what X is before attributing")
- queue wait p95 > 30 s
- spill > 1 GB in 24 h
- commit queue p95 > 10 s
- tables: unsorted > 20%, stats_off > 10, skew_rows > 4 (above 1 GB only)
- any blocked session
- load errors > 0

`list_keys`: tables → schema.table; top queries → normalized-text hash; locks → pid.

## 2. AWS collectors: `collectors/aws/` (one `type: aws` source with a service map)

```yaml
- name: aws_main
  type: aws
  aws: {profile: readonly, region: …}            # or {instance_role: true} when exec is ssh:<host>; never keys in config
  exec: local | ssh:<host>
  services:
    dms: {}                                      # all instances/tasks, capped
    glue: {jobs: ["*"], crawlers: true, catalog_databases: [bronze, silver]}
    s3: {prefixes: ["s3://acme-lake/bronze/", "s3://acme-raw/firehose/"]}   # ONLY these, never account-wide listing
    athena: {workgroups: [primary]}
    firehose: {}
    cloudwatch: {alarms: true}
```

**Read-only enforcement (code, not convention)**
- Every boto3 session gets a botocore `before-call` handler. It allows only operations whose names start with
  `Describe|List|Get|BatchGet|Head`, plus an explicit allowlist (`GetMetricData`, `BatchGetQueryExecution`, `DescribeTableStatistics`).
- Anything else raises before any network call.
- Test: a collector session calling `create_bucket` / `start_replication_task` raises, and moto sees no call.
- Ship `docs/aws-iam-readonly.json`, the minimal IAM policy covering exactly the calls used. A test generates it from the operation allowlist and
  fails if they drift.

**Cost guard**
- CloudWatch is read via batched `GetMetricData` (≤ 500 metrics per call, 1 h period over 24 h).
- The total number of metrics per snapshot is reported, and capped by `options.max_metrics` (default 300).
- Document the approximate cost per snapshot in the collector guide.

**Service sections and signals**
| service | sections | signals |
|---|---|---|
| dms | instances: class, storage, multi-AZ, engine version, CPU/FreeableMemory/SwapUsage (CW 24 h max/avg); tasks: id, type, status, last failure message, CDCLatencySource/Target (CW p95/max), table statistics (errored/suspended tables, top 10 by CDC changes 24 h) | task not running; last failure < 24 h; CDC latency p95 > 300 s; tables errored/suspended; instance memory < 10% or swap > 0 sustained; CPU p95 > 85% |
| glue | jobs: last 5 runs (state, duration, DPU-seconds, error first 300 chars); crawlers: state, last crawl status; catalog: tables per configured database with location and partition keys | failed run in 24 h; duration > 2× median of the previous 4; crawler failed; table with no partitions added in 7 d when partitioned |
| s3 | per configured prefix: object count + bytes (CloudWatch BucketSizeBytes/NumberOfObjects when the prefix is a whole bucket; otherwise capped ListObjectsV2 ≤ 10 pages); newest object time | newest object older than `options.max_age_h` (default 26) |
| athena | per workgroup: last 24 h queries (state counts, data scanned total, top 5 by bytes, failures with reason) | failed queries > 0; a single query > `options.max_scan_gb` (default 100) |
| firehose | streams: status, destination (bucket/prefix), buffering; CW DeliveryToS3.Success, DataFreshness, ThrottledRecords | stream not ACTIVE; freshness p95 > 2× buffer interval; delivery success < 1.0 |
| cloudwatch | alarms in ALARM state (name, metric, since) | each alarm in ALARM |

**Transport**
- Local runs use boto3 directly.
- `ssh:<host>` sends a single module `collectors/aws/_aws_core.py` (stdlib + boto3) over `ssh <host> python3 -`. It uses the remote instance role
  and prints JSON.
- `dea doctor` checks that the remote has `python3 -c "import boto3"` and that `sts get-caller-identity` works. Print the ARN's account
  masked as `****1234`.

**Rendering:** `platform/<source>.md` has one H2 per service. If it goes over 300 lines, split into `platform/<source>/<service>.md` plus an index.
secret_guard must already block `~/.aws/credentials` and `~/.aws/config`; add tests for both.

## 3. AWS lineage edges (extend `scanners/edges.py` to read the latest platform snapshot)

- **DMS:**
  - Table-mapping selection rules (schema/table, wildcards kept as patterns) plus `rename` transformations give the edge
    `source:<schema.table> → dms:<task> → target:<schema.table>` (or an `s3://` node for S3 targets).
  - A wildcard rule becomes a pattern node `src.%` → `tgt.%`, marked `pattern: true`. It is never expanded by guessing.
- **Firehose:** `firehose:<stream> → s3://bucket/prefix`.
- **Glue catalog:** a table's `location` (`s3://…`) is joined to S3 nodes by prefix. Firehose/DMS writing a prefix and a Glue/Athena
  table located there become a reader edge `glue:<db.table>`.
- These edges show in `catalog/edges.md` and in `dea edges` / `dea impact`.
- Test with a fixture snapshot: DMS → S3 prefix → Glue table, plus DMS → Redshift table → dbt model (cross-project).

## 4. Redshift audit pack: `skills/audit/references/redshift.md`

- Generic R1 config/infra, R2 workload attribution (7 d), R3 pressure signals (7 d), R4 inventory/hygiene, and verdict rules, built on `dea query`
  and the AWS collector sections.
- Verdict rules, in order:
  1. Bottleneck layer first: orchestration, fixable waste, CPU, memory, I/O, connections or storage.
  2. Sizing claims need ≥ 7 days of data, with weekday vs weekend reported separately.
  3. Never attribute load by user name alone; establish what the user is.
  4. Hardware last.
- Written fresh as a generic pack. It may follow the structure of a private pack the maintainer has, but no identifiers, thresholds tied to
  a real system, or numbers may come across.
- A grep test in CI fails on a deny-list of strings the maintainer keeps outside the repo in `DEA_DENYLIST_FILE` (env; skipped if unset).
