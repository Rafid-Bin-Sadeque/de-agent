Today an item is done only when the WHOLE text is one struck span (`cli/src/de_agent/lint.py` ~:161 and

closing `~~` appears after the leading date (the date is inside the struck span). Unchanged: an item with a strike
elsewhere (e.g. `- **2026-11-30 x** ~~old idea~~`) is NOT done; table rows keep their State/Status column rule.

## 2. DMS lineage from Terraform-managed tasks

Real repo (`aws_dms_replication_task` built the idiomatic way) gives 0 edges and 1 unresolved ref:

```hcl
data "aws_dms_endpoint" "target" { endpoint_id = var.target_endpoint_id }
resource "aws_dms_replication_task" "demo" {
  replication_task_id = var.task_id                       # variable with a literal default
  target_endpoint_arn = data.aws_dms_endpoint.target.endpoint_arn
  table_mappings      = jsonencode(local.table_mappings)  # built with for-expressions over a locals map
}
```

`cli/src/de_agent/scanners/terraform.py` (`h_dms_task` ~:499, `_dms_rules` ~:485, `Ctx.address` ~:456):

a. `Ctx.address` resolves `data.<type>.<name>.<attr>` as well as resources. A `data.aws_dms_endpoint` target is a
   database target (table keys `schema.table`) unless its attrs say S3; it is not "unresolved".
b. `replication_task_id` from `var.x` resolves to the variable's literal default (check `Ctx.text` does this; the
   catalog currently shows the resource address instead of `dms:<task id>`).
c. Schema/table `rename` transformation rules are applied to the target key (today a renamed schema still produces
   `target = source`, which is wrong: the demo lands `api_backend.*` in `test_api_backend.*`).
d. When the static mapping yields no selection rules (computed `jsonencode(local...)`), fall back to the latest hub
   snapshot: the aws source's `dms_table_mappings` section (0.3.2) rows for that task id give the pairs
   (`schema.table` → `target_schema.target_table`). Mark these edges `via: live-snapshot:<snapshot ts>`, and say in the
   catalog page which tasks used the fallback. No snapshot / task not found → keep today's behaviour and list it under
   unresolved with the reason.
e. Static mapping and snapshot disagree (both available) → catalog warning line `mapping drift: <task>` listing the
   tables only in one side. Do not fail the scan.

Scanner stays parse-only (never runs terraform). The snapshot read is a file read of `.dea/snapshots/<latest>/<aws>.json`.

Tests: fixture repo shaped like the snippet above (data-source target, var task id, locals-built mappings, schema
rename) + a snapshot fixture → 9 pairs with the renamed target schema and `via: live-snapshot`; literal-JSON mapping with
a rename → static pairs with renamed targets; data endpoint no longer unresolved; drift case; no-snapshot case.
