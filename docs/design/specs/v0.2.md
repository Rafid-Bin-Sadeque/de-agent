# v0.2 spec: universal sources, any-code scanners, universal CLI write guard

v0.1 gave the agent eyes only on systems with a hand-written collector. v0.2 makes sources **declarative**: any system with SQL, a CLI
or an HTTP API can be monitored through a *pack* (a small YAML file). It also makes the scanners read any Python, notebook and
Terraform code, and extends the write guard to every common cloud/data CLI. Zero company data. Packs are tested on fictional fixtures
unless marked `validated: live`.

## 1. Packs

### 1.1 Format (`cli/src/de_agent/packs/<name>.yaml`; hub-local `packs/<name>.yaml` overrides a built-in of the same name)

```yaml
pack: snowflake
version: 1
kind: sql                    # sql | cli | http
dialect: snowflake           # sql only; used by the classifier
requires: {extra: snowflake} # or {cli: databricks} / {}
validated: fixtures          # fixtures | live  (shown in docs and `dea pack list`)
description: Warehouses, failed/queued queries, credit use, task and pipe health.
sections:
  - name: failed_queries_24h
    sql: |                   # sql kind: must classify as a read in `dialect`
      select query_id, user_name, error_message, start_time
      from snowflake.account_usage.query_history
      where execution_status = 'FAIL' and start_time > dateadd(hour, -24, current_timestamp())
      order by start_time desc limit 50
    key: query_id            # list_keys for diff
    columns: [query_id, user_name, error_message, start_time]   # optional projection/order
    signals:
      - rows: "count > 0"    # aggregate rule over the section
        message: "{count} failed queries in 24h"
        severity: warn       # info | warn | error
      - when: "error_message contains 'quota'"   # per-row rule
        message: "query {query_id}: quota error"
    render: table            # table | list
```
- **cli kind:** a section has `run: [argv…]` (a list, never a shell string), `select: <JMESPath>`, `fields: {out_name: <JMESPath>}`, and the same `key`, `signals` and `render` as above.
- **http kind:** a section has `get: <path?query>` (relative to the source's `base_url`), or `graphql: <query string>` (must start with `query`/`{`, never `mutation`/`subscription`), plus `select`/`fields`.

### 1.2 Safe expressions
`when:` and `rows:` use a tiny evaluator built on Python `ast` with a whitelist:
- comparisons, `and`/`or`/`not` and arithmetic
- `in`, plus `contains`/`startswith` rewritten to method calls
- names, which are row fields, or `count` for `rows:`
- literals, and the functions `len`, `lower`, `age_h(ts)`, `age_d(ts)` and `now()`

No attribute access, no calls outside the whitelist, no subscripts beyond `field['x']`. Any unsupported syntax is a pack error. Tests must
cover the attempted escapes: `__import__`, attribute chains, lambdas and comprehensions.

### 1.3 Generic collectors
- **`type: sql`**, configured as `{pack: <name>, conn: {url: "<sqlalchemy url>", password: <secret ref>}}`.
  - Uses SQLAlchemy 2.x with the driver from the pack's extra. A missing driver gives the error "pip install 'de-agent[<extra>]'".
  - Every statement is classified with `sqlclass` in the pack dialect before it runs; a write is a pack error and is never executed.
  - Where the database supports it, the statement runs inside a read-only transaction:
    - postgres/redshift: `BEGIN READ ONLY`
    - mysql/mariadb: `START TRANSACTION READ ONLY`
    - mssql: a read-only intent connection where available
  - A per-statement timeout is set where supported (`statement_timeout`, `max_execution_time`, `STATEMENT_TIMEOUT_IN_SECONDS`, `job_timeout`).
  - Local exec only.
- **`type: cli`**, configured as `{pack: <name>, exec: local|ssh:<host>}`.
  - Runs each section's argv with `shell=False`. Over ssh, each argument is `shlex.quote`d after `ssh <host> --`.
  - Before running, the argv must pass the same read-verb classifier as the hook (§3). A non-read argv is a pack error.
  - Output is parsed as JSON. Use `jmespath`, a new pure-Python MIT dependency in the core install.
  - Timeout per section.
- **`type: http`**, configured as `{pack: <name>, base_url, auth: none|bearer|basic|header, token/password: <secret ref>, header_name}`, exec local or `ssh:<host>`.
  - Over ssh, a stdlib urllib remote script is used, like the Airflow collector, with secrets resolved remotely.
  - Only GET and read-only GraphQL POST are allowed, enforced in code. Responses are capped at 5 MB.
- **Everything else** (render, diff, `list_keys`, signals, snapshots, `dea find` indexing, the session hook) works unchanged through the existing collector protocol.
- **The hand-written collectors stay**, as the "deep" tier: postgres, redshift, airflow, dbt, aws.

### 1.5 CLI
- `dea pack list` shows name, kind, validated and source (built-in or hub).
- `dea pack show <name>`.
- `dea pack new <name> --kind sql|cli|http` scaffolds `packs/<name>.yaml` in the hub, with comments.
- `dea pack check <file|name>` validates the schema and expressions, classifies every SQL as a read in the pack dialect, runs the argv read-verb check, and checks http methods.
- `dea pack test <source>` runs the source once, read-only, and prints the rendered page plus the signals.
- `dea doctor` covers pack sources: driver/CLI present, auth, and `pack check`.

### 1.6 `add-source` skill
The user says "we also use X" and the skill:
1. Finds an existing pack with `dea pack list`.
2. If there is none, drafts `packs/<x>.yaml` from the system's documented system views, CLI or API, through the explorer or the docs it already knows.
3. Runs `dea pack check`.
4. Proposes the `de-agent.yaml` source block, with secret refs only, and asks the human to put credentials in env/pgpass.
5. Runs `dea pack test`.
6. Iterates.

**Never-dos:** a write statement or mutating verb in a pack, inline credentials, an account-wide listing (always scope to named resources).

## 2. Scanners for any code

- **`python` scan** (`{type: python, path, globs: ["**/*.py"]}`), static via `ast`:
  - SQL string literals passed to `execute`/`executemany`/`read_sql`/`read_sql_query`/`text()`/`spark.sql`.
  - pandas `read_sql_table(name, schema=)` and `to_sql(name, schema=)` as a write.
  - pyspark `spark.table`/`spark.read.table`/`.saveAsTable`/`.insertInto`/`DeltaTable.forName`, plus `spark.read.format(..).load(path)` and `.save(path)` as path nodes.
  - Per-function edges.
- **Notebooks:**
  - `.ipynb` code cells.
  - Databricks source notebooks: `# Databricks notebook source` with `# COMMAND ----------`; `# MAGIC %sql` cells are parsed as SQL.
  - Both are handled by the python scan, with the notebook path as the node owner.
- **Util attribution** (closes the v0.1 dogfood gap):
  - If a DAG or job calls a util function (via the existing symbol index, or the python scan's call graph within the scanned repo) and that function has SQL/table edges, the caller inherits them with `via: util:<module.func>`.
  - It goes up to 2 hops.
  - The proc `CALL`s inside utils resolve the same way.
  - The test fixture must reproduce the dogfood pattern: a DAG calls `utils.run_proc("schema.sp_x")` and the edge appears.
- **Config-driven dispatch:** a module-level constant list/dict of proc or table names iterated in a loop that calls a util is unrolled, like `for x in CONST`.
- **Bookkeeping ignore list:** `edges.ignore_tables: [etl.load_state, …]` in `de-agent.yaml`. Ignored tables keep their own edges but are not traversed by `impact`.
- **`terraform` scan** (`{type: terraform, path}`):
  - Parsing uses `python-hcl2` when installed (extra `terraform`), with a regex fallback for `resource "<type>" "<name>"` blocks.
  - It catalogs the resources (type, name, file:line).
  - Data-relevant types become nodes with edges where the attributes name them: DMS tasks/endpoints, Glue jobs/crawlers/tables, BigQuery datasets/tables, Snowflake databases/tables/tasks, Databricks jobs, MWAA/Composer, Kinesis/Firehose, S3/GCS buckets, Pub/Sub topics/subscriptions.
  - Output goes to `catalog/terraform/<scan>.md`.

## 3. Universal CLI write guard (hook; stdlib + vendored sqlglot; Python 3.9)

New `scripts/cli_guard.py`, registered on Bash, which shares `de_agent/clients.py` with the other hooks. For these CLIs, classify the
subcommand as read or write. A **write** is denied unless it is executed through `dea apply` (an approved shell step). An **unknown verb** of a known CLI
is denied with "not a recognised read-only command; put it in a plan as a shell step" (fail closed).

**Covered:**

- **aws:**
  - Read: `describe-*`, `list-*`, `get-*`, `head-*`, `batch-get-*`, `lookup-*`, `s3 ls`, `s3 cp|sync` with an s3 source and a local destination, `sts get-caller-identity`.
  - Write: everything else, including `s3 cp|mv|sync` to s3, `s3 rm`, and `start-*`/`stop-*`/`create-*`/`delete-*`/`update-*`/`put-*`/`modify-*`/`run-*`/`invoke`/`terminate-*`/`reboot-*`.
  - `redshift-data`/`athena` keep their SQL handling.
- **gcloud and gsutil:**
  - Read: `list`, `describe`, `get-*`, `logs read`, `storage ls|cat`, `config list`, `auth list`.
  - Write: `create`, `delete`, `update`, `deploy`, `run`, `jobs submit`, `set-iam-policy`, `storage cp|mv|rm` to `gs://`, and the like.
- **bq:**
  - `bq query` keeps its SQL handling. `ls`/`show`/`head` are read.
  - `mk`/`rm`/`cp`/`load`/`insert`/`update`/`extract` are write.
- **databricks:**
  - Read: `list`/`get`/`list-runs`/`get-run`/`export`/`fs ls`/`fs cat`.
  - Write: `run-now`, `submit`, `create`, `delete`, `reset`, `cancel*`, `fs rm|cp|mv` to dbfs, `clusters start|delete|edit`, `bundle deploy|run`.
  - `databricks sql` / `dbsqlcli -e`: the SQL is classified.
- **kubectl:**
  - Read: `get`, `describe`, `logs`, `top`, `explain`, `version`, `config view|get-contexts|current-context`, `auth can-i`, `api-resources`.
  - Write: `apply`, `create`, `delete`, `edit`, `patch`, `replace`, `scale`, `rollout restart|undo`, `cordon`, `drain`, `label`, `annotate`, `set`, `cp` into a pod, `port-forward`.
  - `exec`: recurse into the argv after `--` (a client inside → SQL guard; anything else → write).
- **helm:**
  - Read: `list`, `status`, `get`, `history`, `show`, `template`.
  - Write: `install`, `upgrade`, `uninstall`, `rollback`.
- **terraform and tofu:**
  - Read: `plan`, `show`, `validate`, `fmt -check`, `output`, `state list|show`, `providers`, `version`, `init`.
  - Write: `apply`, `destroy`, `import`, `state rm|mv|push`, `taint`, `untaint`, `force-unlock`.
- **pulumi:**
  - Read: `preview`, `stack ls`, `config get`.
  - Write: `up`, `destroy`, `refresh --yes`, `import`.
- **az:**
  - Read: `list`, `show`, `get-*`, `query`, `account show`.
  - Write: `create`, `delete`, `update`, `set`, `start`, `stop`, `restart`, `run`, `invoke`.
- **snow** (Snowflake CLI):
  - `snow sql -q` is classified as SQL. `object list|describe` is read.
  - Everything else is write.
- **dbt:**
  - Read: `parse`, `compile`, `ls`/`list`, `docs generate`, `debug`, `deps`, `source freshness`, `test` (tests only select).
  - Write: `run`, `build`, `seed`, `snapshot`, `run-operation`, `retry`.
- **airflow:**
  - Read: `dags list|show|state|list-runs|list-jobs|report|details`, `tasks list|state|states-for-dag-run`, `version`, `config get-value|list`, `connections list` (a secret_guard rule covers `connections get`/`export`).
  - Write: `dags trigger|pause|unpause|delete|backfill|reserialize`, `tasks clear|run|test`, `db *`, `users *`, `variables set|delete|import`, `pools set|delete`.
- **dagster and prefect:**
  - Read: list/inspect verbs.
  - Write: `job launch|execute`, `deployment run`, `flow-run cancel|delete`, and the like.
- **kafka-topics and kafka-configs:**
  - Read: `--list`, `--describe`.
  - Write: `--create`, `--delete`, `--alter`.
- **docker and docker compose:**
  - `exec`/`run`: recurse into the inner argv.
  - Other verbs are out of scope; dev tooling stays allowed.

Wrappers (`env`, `sudo`, `bash -c`, `xargs`, `find -exec`, `timeout`, `nice`, `uv run`, `poetry run`) recurse as in sql_guard. guard
`mode: ask` turns a deny into ask. A hub may add `guard.cli_allow: ["dbt run --select staging"]` (exact prefixes, human-edited; self_guard
protects the key like `guard:`). Corpus ≥ 300 cases (allow + deny per CLI, wrappers, ask mode, cli_allow).

## 6. Release tooling
`tools/release.sh` v2: when `origin/main` (or `--base <ref>`) exists, the release commit's parent is that ref, not an orphan. The public
history stays linear with one commit per release, and pushes are fast-forward. It takes `--version 0.2.0` and tags `v0.2.0`. The greps run over the
new tree and the new commit's diff, plus the whole public history. The first-release orphan path is kept for `--base none`.
