# Knowledge architecture — how context scales from 1 to 500 projects

Design rationale (the user-facing version is [docs/architecture.md](../architecture.md)). Extends [PLAN.md](PLAN.md) §4. Drives the M1 (collectors, index) and M2 (skills) specs.

## 1. The rule: every fact has exactly one home, chosen by how fast it changes

| Kind of fact | Example | Home | Who writes it | Loaded |
|---|---|---|---|---|
| Live state | last DAG runs, CDC lag, table bloat, node type | `platform/` (generated) | collectors (`dea snapshot`) | on demand; staleness warned at session start |
| Structure that code already encodes | DAG list + schedules, which job reads/writes which table, dbt lineage, util → caller map | `catalog/` (generated) | static scanners (`dea scan`) | on demand, via `dea find` |
| How things connect (the non-derivable part) | contracts, conn IDs, "A must finish before B or X breaks" | `integrations/<a>--<b>.md` | humans (hub-sync skill drafts) | when working on that seam |
| What a project is and its gotchas | purpose, owners, conventions, traps | `projects/<name>.md` | generated header + human body | when that project is touched |
| How to edit code in this repo | commands, style, never-dos | repo `CLAUDE.md` (root ≤ 100 lines) + nested `CLAUDE.md` per big folder | humans | automatically, root at start, nested only when Claude works in that folder |
| What's in flight | dated checks, open issues, waiting-on | `status.md` | hub-sync skill | due/overdue rows injected at session start |
| Secrets | passwords, tokens | **never in the hub**: env vars, `~/.pgpass`, AWS profiles, ssh hosts | — | referenced by name in `de-agent.yaml` only |

Consequences:
- A README or CLAUDE.md is never the knowledge store. It points to the hub and holds only repo-local working rules.
- Anything a script can derive is generated, never hand-written, so it can't go stale or drift.
- Hand-written pages shrink to what only a human knows. That is what keeps them small at any scale.

## 2. Progressive disclosure: three hops, each one small

```
session start (always loaded, ≤ ~1,500 tokens)
  map.md ............ domains (≤ ~20 lines) + platform health line + pointers
     │  one hop
     ▼
domains/<domain>.md . one line per project in that domain (≤ ~60 lines)
     │  one hop
     ▼
projects/<name>.md .. one page: generated facts header + human body (≤ ~150 lines)
     │  only if needed
     ▼
catalog/, platform/, integrations/, repo code via explorer subagent
```

- With ≤ 15 projects, `map.md` lists projects directly and `domains/` is skipped. `dea lint` says when to split
  (map over budget → split it by domain).
- Lookups don't walk the tree. `dea find <term>` jumps straight to the right page (§4).
- Budgets are enforced by `dea lint`, not by good intentions: map ≤ 1,500 tokens, domain page ≤ 60 lines,
  profile ≤ 150 lines, root CLAUDE.md ≤ 100 lines, nested CLAUDE.md ≤ 60 lines.

## 3. Big repos (e.g. an Airflow monorepo with 100+ DAGs and shared utils)

Problem: reading the folder costs tens of thousands of tokens, and a giant CLAUDE.md costs tokens on every turn.

| Layer | What | Size |
|---|---|---|
| Root `CLAUDE.md` | deploy model, operator/hook conventions, never-dos, pointer to the hub profile | ≤ 100 lines |
| Nested `dags/<domain>/CLAUDE.md` | rules for that domain only; Claude Code loads it only when it works in that folder | ≤ 60 lines each |
| `catalog/airflow/<repo>.md` (generated by `dea scan airflow`) | one line per DAG: id · schedule · owner · tags · file · upstream datasets/sensors · tables read/written (sqlglot over SQL strings + `CALL proc` names), grouped by domain/tag | ~1 line per DAG |
| `catalog/symbols/<repo>.md` (generated, Python AST) | shared util function → which DAGs call it ("change `pg_utils.copy_df` → 14 DAGs affected") | 1 line per symbol |
| `platform/airflow.md` (generated, REST API) | live: last runs, failures, import errors, paused, durations | — |
| explorer subagent | anything else: reads code in its own context and returns the conclusion | 0 tokens in main context |

So "which DAG loads `orders_mart` and what breaks if I change `copy_df`?" costs two catalog lookups, not a repo read.

## 4. `dea find`: fast retrieval without a vector DB

- A local SQLite FTS5 index (Python stdlib, no service) over hub pages, catalogs and the latest platform snapshot, rebuilt
  incrementally on `dea snapshot` / `dea scan` / file change. Typical query < 50 ms at 10k pages.
- Tuned for **exact identifiers**: table names, DAG ids, task ids, hostnames, and error strings tokenized on `_ . - /`.
  This is where embeddings are weakest and engineers search most.
- Output: ranked `path:line — snippet`, so Claude opens 1–2 small files instead of grepping repos.
- An optional semantic layer (embeddings) can come later behind the same command, for fuzzy questions over large prose
  (runbooks, incident notes). It is not needed for v1.

## 5. "How projects talk to each other": generated first, written second

`dea scan` derives cross-project edges with no human input:
- dbt `manifest.json`: model → model lineage, sources, exposures
- Airflow: Dataset producers/consumers, ExternalTaskSensors, TriggerDagRunOperator
- SQL in DAGs/procs (sqlglot): tables read vs written; `CALL schema.proc` → proc owner
- CDC/ingest collectors: source DB table → replication task → landing table

These are joined into `catalog/edges.md`: "`orders_mart` is written by `acme_airflow:orders_dag`, read by
`dbt:analytics.fct_orders`, fed via `dms:task-3` from `app_db.orders`". An integration page is written only for what
edges can't express (contract, timing, gotchas). hub-sync proposes one when it sees a new edge with no page.

## 6. Scale properties (100s of projects, many engineers)

| Concern | Mechanism |
|---|---|
| Always-loaded context stays flat | map lists domains, not projects; the budget is enforced by lint |
| Lookup cost stays flat | FTS index; 3-hop ceiling |
| Freshness without toil | generated layers (platform, catalog, edges, profile headers) refresh on schedule (cron/CI/Airflow DAG) |
| Ownership | profile frontmatter `owner`, `domain`, `repo`, `tags`; CODEOWNERS on `projects/<domain>/` |
| Collector speed | per-source parallel, incremental (only changed repos re-scanned via git HEAD), per-source timeouts |
| Many people editing | plain markdown in git, review via PRs, and `dea lint` in the hub's CI blocks broken links/budgets |
| Durability | snapshots versioned (`.dea/snapshots/`), JSON schemas versioned per collector, renderers deterministic |
| Modularity | collectors/scanners are plugins behind one protocol (`name, requires, collect()/scan() → dict`); adding Snowflake = one file + fixtures |

## 7. Migrating an existing hand-written hub

| typical hand-written hub | de-agent |
|---|---|
| `_map.md` imported via every project's CLAUDE.md | `map.md` injected by the SessionStart hook (no CLAUDE.md edits in any repo) |
| `projects/*.md` hand-written | `projects/*.md` = generated header + human body |
| `integrations/*.md` | `catalog/edges.md` (generated) + integration pages for the non-derivable |
| `infra/*.md` + `bin/snapshot-infra.sh` | `platform/*.md` + `dea snapshot` (collectors, incl. `exec: ssh:<host>`) |
| graphify merged graph | `catalog/symbols` + `catalog/edges` + `dea find` (graphify stays optional) |
| `status.md` | `status.md` (same; due rows injected) |
| memory files for project state | status.md + profiles; memory only for personal preferences |
| db-runner / executor / Explore agents | runner / executor / explorer (+ enforced guard instead of a prompt rule) |
| db-audit skill (Redshift pack) | audit skill (Postgres + Redshift packs) |

Dogfooding (M5): a real hand-written hub is migrated onto de-agent before v0.1.0.
