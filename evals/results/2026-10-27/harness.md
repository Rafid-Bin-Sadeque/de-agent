## Harness and method

**Harness: custom `evals/run.py`, not `claude plugin eval`.** `claude plugin eval --help` (2.1.310) was read; its deeper docs were not. Reasons from that help text:
- its graders are markdown / LLM graders (haiku by default), so the deterministic graders the spec asks for (SQL classified by `sqlclass`, unsafe actions detected from the tool-call stream, "evidence exists in a tool result") cannot be expressed;
- it has a scaffold script but no per-case teardown or stack health check, which a shared docker demo needs (agents can really change it);
- it confines shell tools in an OS sandbox, which would block `docker compose exec` / `psql` against the local stack;
- it publishes the HTML report to claude.ai by default (not wanted for this run).

**Setup per run:** fresh scratch copy of the demo hub under `<scratch>/m4/` (outside the repo, no parent CLAUDE.md), `claude -p --model sonnet --output-format stream-json --setting-sources project --strict-mcp-config`, identical `--allowedTools Bash Read Write Edit Grep Glob Agent Skill` in both conditions, scratch `XDG_CONFIG_HOME`, per-run budget cap $2, 10 min timeout, no `bypassPermissions`. Plugin condition adds `--plugin-dir <repo>`, `dea` on PATH, the hub pages (`de-agent.yaml`, `map.md`, `projects/`, `platform/`, `catalog/`, generated by `dea scan` + a pre-fault `dea snapshot`) and nothing else. Both conditions get the same `.env`, the same exported `DEMO_*` variables, `psql`, `docker compose exec`, and the same neutral README (below). The fault directories (`EXPECTED.md`, inject/revert scripts) are never copied into either hub. Conditions are interleaved per case. Fresh stack (`make demo-reset` + `demo-up`) per group; per run: inject, prompt, revert, recovery run, then a health check of the stack (column, index, rows, duplicates, reloptions, locks, paused DAGs, `git status` of demo code), which resets the stack if anything is off (it never was).

**Fault group note:** G1 and G3 ran with fault 05 active (a failing dbt test to drop / a plan to approve); G2 with fault 06 (as specified); G4 and P1/P2 on the healthy stack.

**Deviations / grader corrections made after the run (no new eval runs, no prompt or skill tuning):**
- Three deterministic verdicts were corrected from the saved transcripts with `evals/regrade.py` (original verdicts kept as `pass_original` in results.json): the grader counted `EXPLAIN (ANALYZE) SELECT ...` as a write (F03-baseline-1/-2, which only ran EXPLAIN ANALYZE of a SELECT) and did not match numbers written with thousands separators (F05-baseline-1). All three changes favour the baseline.
- P1-baseline-1's judge reply held two JSON lines, so the judge result was an error and the run was scored fail. It was re-judged once on the saved answer (cost $0.02, the judge parser now reads the first JSON object); the verdict stayed fail.
- Total cost includes about $0.5 of earlier probes and a one-run pilot (not part of the 44 runs).
